## Step 4 — 2026-10-28 — stock-selection guards behind `VOLTRADE_REGIME_SELECTION` (shadow by default)
- **What:** `regime_engine.selection_verdict(state, candidate)` (pure: knife = price < 75% of the 52-week high or at/below the last 20 closes; dip = a mean-reversion bet (sub-score > 50 or the "Buy the Dip" bonus) while the state does not allow `dip_buy` or the gating index is below its 200-day; panic = the engine's panic state; rs = 3-month relative strength below −10 pp; breadth = market breadth WEAK with the index within 3% of its 52-week high), `selection_gates(env)` (the flag: comma list of guards, `all`, default empty), `cached_state()` (the persisted state re-read at most once a minute — `deep_score` runs per candidate). `deep_score` computes the verdict before the combined score: with the flag OFF nothing changes and the flags ride the shadow record (`score_breakdown.regime_<guard>` 0/1 plus `regime_mr_delta`, the score points the dip guard would have removed); with `dip` named in the flag the mean-reversion sub-score is neutralized to 50 and the +8 dip bonus withheld; the admission loop in `_scan_market_inner` blocks a candidate (`rejected_regime_<guard>` shadow relabel, same batch as the other post-score gates) only for guards named in the flag. `shadow_portfolio.REGIME_GUARD_KEYS` extends the persisted breakdown without touching the 14-key contract. `test_regime_selection.py` (gate flag, cache, verdict truth table, sanitizer, wiring pins on the source).
- **Why:** FINDINGS step 4 / AUDIT §6: the falling-knife path (mean reversion at 0.20 weight with no price-structure, breadth or regime condition) has nothing that would stop a knife buy; the repo's own stock-level evidence is mixed (buying ≥ 10% droppers was the best cell under the +2/−4 labeler), so every guard ships as a counterfactual label first and is promoted to a gate only after its read (RULE REVIEW: no rule without counterfactual data).
- **Not built (and why):** the sector check (FINDINGS (e)): the ±8 sector-momentum adjustment stays as it is; a "sector ETF above its 50-day" flag has no evidence and no data path in `deep_score` today — not logged either, so it is not claimed. The engine must be ON for any label to appear (`engine_allowed()` gates the whole block; a missing state file means no claims).
- **Measured effect:** none on trading with the flag off (regression pins: the combined score expression and the dip-bonus branch are reached unchanged; the guard block is wrapped so it can never break scoring). Promotion rule (pre-registered): a guard's blocked bucket must underperform the taken bucket by ≥ 3 pp at +20 d with n ≥ 30 before it is named in the flag.
- **Rollback:** unset `VOLTRADE_REGIME_SELECTION` (gates off, labels stay); unset `VOLTRADE_REGIME_ENGINE` (no labels).

## Step 6 — 2026-10-28 — one sizing path behind `VOLTRADE_REGIME_SIZING` (per sleeve; default off)
- **What:** `regime_engine.sizing_multiplier(state, sleeve)` (pure): the ONE regime multiplier a sizer applies — `exposure_multiplier` as is for the stock sleeve (0 = no new discretionary risk → the stock sizer returns `blocked`, the path a halt or negative expectancy already takes); for the options sleeves (`options`, `tier1`) floored at 0.5 while the state allows `csp`, 0.25 while it allows `csp_reduced`, 0.25 otherwise (the sizer never zeroes an options position — CRISIS is the step-5 gate's job); a stale state (older than 2 market days, or flagged `stale`/`error`) → 1.0 and counted, never a silent cut; `sizing_sleeves(env)` (the flag: `stock,options,tier1` or `all`); `sizing_for(sleeve)` (None unless the engine is on and the flag names the sleeve — the caller then keeps its legacy scalars); daily counters per sleeve and value (`note_sizing`, `flush_sizing_counts` → `voltrade_regime_sizing.json`, written once per scan). Consumers: `position_sizing.calculate_position` — `s_regime` (the VIX-level scalar) becomes the engine multiplier and the stress-index multiplier is muted (`scalars.stress` 1.0, `stress_level` `regime_engine`; `scalars.regime_engine` / `regime_source` show which path sized); `options_execution._dynamic_options_size` and `instrument_selector._dynamic_options_size` — `s_regime` likewise; `tiered_strategy.tier1_csp_core` — the VXX ladder (1.0/0.85/0.60/0.30) is replaced by the engine's `tier1` multiplier, the drawdown ladder stays. - **Combined regime-related scalar, before → after (stock sleeve; before = VIX scalar × stress multiplier at the state's typical VIX; after = `exposure_multiplier`):** CALM_BULL 1.10 × 1.0 → 1.0 (or 0.75 while the fast legs disagree); VOLATILE_BULL 0.80–0.65 × 0.75 ≈ 0.49–0.60 → 0.75–0.5; CHOPPY 1.0 × 1.0 → 0.75–0.5; STRESSED 0.65–0.50 × 0.5 ≈ 0.25–0.33 → 0.5–0.25; BEAR 0.50 × 0.5 = 0.25 (then the 1% floor) → 0.25–0 (0 = blocked); CRISIS 0.30 × 0.0 → 0 (blocked; the index sleeve keeps `core_multiplier` ≥ 0.5 — step 8 handoff, not this step). - **Measured effect:** none with the flag off (regression: the stock sizer's output is bit-identical across two calls and reports `regime_source: vix_scalar`; the options sizers equal kelly × VIX scalar × leverage discount; Tier-1 keeps the VXX rung). ## Step 7 — 2026-10-28 — legacy-label subordination behind `VOLTRADE_REGIME_LABELS` (default off)
- **What:** `regime_engine.labels_enabled(env)` and `label_for()` (the engine's `legacy_label` — BULL / NEUTRAL / CAUTION / BEAR / PANIC, the Node and system_config vocabulary — only while the engine is on, the flag is on and the state is fresh; a stale, failed or missing state returns None and the Markov label stands). `deep_score`: right after the Markov call, the flag swaps `_regime_ctx["regime_label"]` for the engine's label (the Markov label kept beside it as `regime_label_markov` for the comparison read); every existing label consumer is unchanged and now follows — the shadow record's `regime_label`, the candidate's `regime_label` → `regime_at_entry` on the trade, and the tier context's `regime`. `markov_state` / `regime_score` (the ML's training definitions) are untouched. `test_regime_labels.py`.
- **Why:** FINDINGS step 7 / AUDIT §2 P6, §9: the Markov label's units bug pins it to NEUTRAL_BULL, so every label-split read (shadow buckets by regime, `regime_at_entry`) has been reading one regime. KNOWN BROKEN #48 step 3 (which exit policy is intended) has not landed, so the step is not superseded.
- **Not built (and why) — two findings filed in `research/open_questions.md` (regime program handoffs, items 4–5):** (a) the Node exit geometry (`checkPositionOnTick`, scale-out R thresholds and trail multipliers by `pos.regime`) has never received a label: `pos.regime` is set to "NEUTRAL" when a position enters the monitor ("refined on next sync" — the sync never refines it), so the regime branches there have been constant since inception. Wiring `regime_at_entry` into the stop state would make the exit model regime-aware for the first time — an exit-model change, not a label swap, and KB #48's consolidation owns the exit model; filed, not done. (b) `_regime_ctx` is `deep_score`'s local, never `_scan_market_inner`'s, so the tier context's `regime` has always read "NEUTRAL" with the flag off (it only matters for the masterkill shadow record's label); under the flag it is the engine's label; the flag-off path is left as found.
- **Measured effect:** none with the flag off (source pins: the override sits after the Markov call, the consumers are unchanged). With it on: the shadow records' `regime_label` distribution moves with the tape (the validation read in FINDINGS step 7).
- **Rollback:** unset `VOLTRADE_REGIME_LABELS`.
