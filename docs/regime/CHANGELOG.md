## Step 2 — 2026-10-28 — `regime_engine.py` behind `VOLTRADE_REGIME_ENGINE` (shadow)
- **What:** the single owner of regime state (`RegimeState`: primary trend from the slow 120–240-day ensemble with ±1% bands and a 6-day majority filter; fast 22/65-day legs that only downgrade exposure; EWMA-vol state with hysteresis and a `VIX/VIX3M` crisis flag; basket breadth; Daniel–Moskowitz panic state; composite + legacy label; quarter-stepped `exposure_multiplier` with fast-out / glide-in; `core_multiplier ≥ 0.5`; allowed strategies; confidence; dwell; flip budget with alarm; stress flags; Fed EBP), the daily input builder (Alpaca batch → Yahoo fallback, cached per day), persistence (`voltrade_regime_state.json` + append-only `voltrade_regime_history.jsonl`), the daemon method `regime_state`, the config mirror `REGIME_ENGINE_ENABLED` (off), and the engine as `engine_*` arms in the backtest tool (one implementation). 33 tests.
- **Why:** AUDIT §2 found five regime vocabularies and no owner; RESEARCH §6 ranks the inputs this state is built from; FINDINGS step 2.
- **Evidence / measured effect (tool, SPY 2007–2026, same window as Step 1):** `engine_quantized` (what consumers will read) 8.34% CAGR / −20.5% max DD / Sharpe 0.76, 9.4 exposure-level changes/yr, 89% time in market; episodes: 2008 DD −17.1%, 2020 −15.2%, 2022 −11.0%, 2015–16 −7.5% CAGR, late 2018 −17.0% annualized; `engine_core` (the never-fully-out multiplier for the index sleeve) 9.26% / −36.7% / 0.72. Primary (slow-trend) flips 2.7/yr after the filter (4.7 raw; research budget 0.5–2, alarm 6); composite changes 3.2/yr. Pre-registered flip ablation: widening the band to 2–3% cut raw flips to 3.1–2.2/yr at −0.3 pp CAGR — rejected (three variants tried, documented value kept). With the flag off nothing runs; with it on, one computation per scan (7.6 s cold on the Yahoo fallback, 0 s on the daily cache) and no consumer.
- **Rollback:** unset `VOLTRADE_REGIME_ENGINE` (and keep `REGIME_ENGINE_ENABLED` false); the state file is inert.

## Step 4 — 2026-10-28 — stock-selection guards behind `VOLTRADE_REGIME_SELECTION` (shadow by default)
- **What:** `regime_engine.selection_verdict(state, candidate)` (pure: knife = price < 75% of the 52-week high or at/below the last 20 closes; dip = a mean-reversion bet (sub-score > 50 or the "Buy the Dip" bonus) while the state does not allow `dip_buy` or the gating index is below its 200-day; panic = the engine's panic state; rs = 3-month relative strength below −10 pp; breadth = market breadth WEAK with the index within 3% of its 52-week high), `selection_gates(env)` (the flag: comma list of guards, `all`, default empty), `cached_state()` (the persisted state re-read at most once a minute — `deep_score` runs per candidate). `deep_score` computes the verdict before the combined score: with the flag OFF nothing changes and the flags ride the shadow record (`score_breakdown.regime_<guard>` 0/1 plus `regime_mr_delta`, the score points the dip guard would have removed); with `dip` named in the flag the mean-reversion sub-score is neutralized to 50 and the +8 dip bonus withheld; the admission loop in `_scan_market_inner` blocks a candidate (`rejected_regime_<guard>` shadow relabel, same batch as the other post-score gates) only for guards named in the flag. `shadow_portfolio.REGIME_GUARD_KEYS` extends the persisted breakdown without touching the 14-key contract. `test_regime_selection.py` (gate flag, cache, verdict truth table, sanitizer, wiring pins on the source).
- **Why:** FINDINGS step 4 / AUDIT §6: the falling-knife path (mean reversion at 0.20 weight with no price-structure, breadth or regime condition) has nothing that would stop a knife buy; the repo's own stock-level evidence is mixed (buying ≥ 10% droppers was the best cell under the +2/−4 labeler), so every guard ships as a counterfactual label first and is promoted to a gate only after its read (RULE REVIEW: no rule without counterfactual data).
- **Not built (and why):** the sector check (FINDINGS (e)): the ±8 sector-momentum adjustment stays as it is; a "sector ETF above its 50-day" flag has no evidence and no data path in `deep_score` today — not logged either, so it is not claimed. The engine must be ON for any label to appear (`engine_allowed()` gates the whole block; a missing state file means no claims).
- **Measured effect:** none on trading with the flag off (regression pins: the combined score expression and the dip-bonus branch are reached unchanged; the guard block is wrapped so it can never break scoring). Promotion rule (pre-registered): a guard's blocked bucket must underperform the taken bucket by ≥ 3 pp at +20 d with n ≥ 30 before it is named in the flag.
- **Rollback:** unset `VOLTRADE_REGIME_SELECTION` (gates off, labels stay); unset `VOLTRADE_REGIME_ENGINE` (no labels).
